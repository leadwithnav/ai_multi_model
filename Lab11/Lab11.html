Lab 11

Context Continuity vs. Handoff Architectures

Evaluating Uncoordinated Parallel Execution (NO_HANDOFF) vs. Contract-Driven Architecture Handoff (HANDOFF)

Goal

Compare independent parallel execution against spec-driven contract handoffs between builder and QA subagents across explicit vs. ambiguous task requirements:

Strategy 1
NO_HANDOFF (Independent Execution)

The coordinator invokes TERRA Builder and LUNA QA independently directly from raw requirements. No shared architectural contract (design.md) is generated.

Strategy 2
HANDOFF (Shared Spec Contract)

The coordinator first delegates to SOL Architect to create an explicit specification (design.md). Both TERRA Builder and LUNA QA then build and test against the shared blueprint.

Evaluation & Metrics Pipeline

After running both strategies, run-analyzer calls measure_metrics.py for execution telemetry and evaluates whether lack of handoff causes contract drift and test suite failures between Builder implementation and QA tests.

Architecture Flow Topology

Visualizing uncoordinated parallel subagent dispatch vs. contract-driven handoff:

NO_HANDOFF HANDOFF ───────────────── ───────────────── TASK TASK / \ │ / \ ▼ ▼ ▼ SOL Architect TERRA LUNA │ Builder QA ▼ │ │ design.md ▼ ▼ / \ solution tests / \ ▼ ▼ TERRA LUNA Builder QA │ │ ▼ ▼ solution tests

Subagent Team Roster

Agent Name File Location Model Binding Primary Role

Strategy Comparison & Architecture Flow

Understanding the trade-offs between uncoordinated parallel execution and contract-driven architecture handoffs:

Metric / Dimension NO_HANDOFF Strategy HANDOFF Strategy
Execution Flow Coordinator → Parallel (TERRA Builder & LUNA QA) Coordinator → SOL Architect (design.md) → (TERRA Builder & LUNA QA)
Latency & Speed Lowest Latency (Skips Architect phase) Higher Latency (Sequential Architect turn required)
Token Cost Lowest Token Usage Higher Token Usage (Blueprint generation + prompt context)
Contract Alignment (Explicit Tasks) 100% Pass Rate (Equal Alignment) 100% Pass Rate (Equal Alignment)
Contract Alignment (Ambiguous Tasks) High Risk of Contract Drift (Code/Test mismatch) 100% Contract Alignment & High Pass Rate
Recommended Use Case Explicit tasks with unambiguous API schemas Ambiguous requirements needing upfront architectural clarification
