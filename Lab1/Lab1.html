1. What This Course Is Really About

Throughout the course, you will work with one application: order-flow-service.

It is a small, realistic order-processing service built with FastAPI and SQLAlchemy. It:

    Accepts orders Checks and reserves inventory Calls a payment gateway Processes payment webhooks Applies basic rate limiting

The repository contains deliberately planted production-style defects, including examples involving:

Concurrency
Retries & Timeouts
Security Defects
Financial Precision
Rollback / State Consistency
Engineering Focus: The purpose is not to teach basic debugging. A capable coding model can fix individual defects. The harder engineering questions are:
  • Which model should handle each task?
  • How do we prove the generated fix actually works?
  • What does each choice cost in time and budget?
  • When should we use a stronger model?
  • What happens when a model or provider fails?
  • How do we avoid tightly coupling our coding workflow to one vendor?

4. Prerequisites

Before executing the setup steps, ensure you have:

    AWS Account or instructor-provided AWS training credentials Terminal Access (Bash, Zsh, or Windows PowerShell) Python 3.9+ Node.js & npm Git
Corporate Classroom Recommendation: If temporary or pre-provisioned AWS identities are supplied by your instructor, use those credentials instead of creating long-lived IAM access keys on personal AWS accounts.

Step 1 — Configure AWS Access

Configure a named AWS CLI profile dedicated to the course. Do not use the AWS root user.

Terminal / Shell Command 
aws configure --profile order-flow-course

Provide the following when prompted:

Prompt KeyValue to Enter
AWS Access Key ID<your access key>
AWS Secret Access Key<your secret key>
Default region nameus-east-1 (or instructor region)
Default output formatjson

Verify your authentication identity:

Verification Command 
aws sts get-caller-identity --profile order-flow-course

Expected Result: AWS returns your account ID, IAM User ARN, and User ID JSON block.

Step 2 — Confirm Bedrock Model Access

Open Amazon Bedrock in the AWS Management Console and verify model access.

The course utilizes multiple vendor model families via Amazon Bedrock:

Anthropic Claude

Claude 3.5 Sonnet, Claude 3.5 Haiku, Claude 3 Haiku

Amazon Nova & Open Models

Amazon Nova Pro / Lite / Micro, Meta Llama 3 models

Model IDs are kept decoupled in COURSE_MODELS.md so workflows remain stable across regional deployments.

Confirm that the AWS CLI v2 is properly installed on your machine:

Terminal

Create a fresh virtual environment inside your course workspace:

Terminal

Terminal

Step 7 — Configure OpenCode for Amazon Bedrock

Ensure opencode.json exists in your lab directory with Bedrock provider configuration:

opencode.json
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "amazon-bedrock": {
      "options": {
        "region": "us-east-1"
      }
    }
  }
}

Set AWS Environment variables in your terminal session:

Bash
export AWS_PROFILE=order-flow-course
export AWS_REGION=us-east-1
PowerShell
$env:AWS_PROFILE="order-flow-course"
$env:AWS_REGION="us-east-1"

Ask OpenCode to list accessible Amazon Bedrock models:

Terminal
opencode models

Troubleshooting & Common Issues

Verify your profile configuration with:

aws configure list --profile order-flow-course

Ensure access key and secret key are entered without trailing spaces or quote marks.

Check active terminal environment variables:

echo $AWS_PROFILE
echo $AWS_REGION

Ensure region in opencode.json matches region with Bedrock model access permissions.

Confirm Node.js npm global bin path is in your system PATH:

npm list -g --depth=0
