Step 2 — Task Requirements

Each model receives the exact same implementation requirement task defined in benchmark/TASK.md:

benchmark/TASK.md
Implement the in-memory rate limiter in:

../order-flow-service/src/utils/rate_limiter.py

Requirements:

1. Allow a configurable maximum number of requests per time window.
2. Reject requests after the limit is reached.
3. Requests must become eligible again after the window expires.
4. Different client IDs must be tracked independently.
5. The implementation must behave correctly under concurrent access.
6. Do not change public function signatures.
7. Do not modify unrelated files.
8. Keep the implementation simple and maintainable.

When finished, return a short summary of what you changed.

Step 4 — Execute Models One by One

Run each model individually following the 5-step loop below:

Execution Loop For Each Model:
    Run OpenCode command and note the wall-clock Latency (seconds) and token Cost. Run acceptance tests: cd ../order-flow-service && pytest -q tests/ && cd ../Lab1 Record Tests Passed and Quality Bar (PASS if 100% pass rate, else FAIL). Reset repository: .\reset.ps1 (Windows) or ./reset.sh (Linux/macOS). Repeat for the next model.
How to Measure Latency, Tokens & Cost
1. Latency (Seconds)

Measure total execution time using timing commands:

    PowerShell: Measure-Command { opencode run --agent claude-3-5-sonnet "$(Get-Content benchmark/TASK.md -Raw)" } Bash: time opencode run --agent claude-3-5-sonnet "$(cat benchmark/TASK.md)"
2. Token Counting

Pass --format json to stream JSON events containing exact token counts (tokens.input, tokens.output):

opencode run --agent claude-3-5-sonnet --format json "$(cat benchmark/TASK.md)"
3. Cost Calculation ($ USD)

Calculate cost using Amazon Bedrock pricing per 1 Million tokens:

Cost = (Input_Tokens / 1M * Input_Price) + (Output_Tokens / 1M * Output_Price)
