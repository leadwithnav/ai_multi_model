Lab 10

Automatic Prompt Optimization Evaluation

Evaluating the Impact of Automated Prompt Optimization on Code Quality, Token Costs, Latency & Execution Metrics

Goal

Evaluate whether automated prompt optimization improves code quality for lower/mid-tier coding models, and quantify its trade-offs on latency, cost, and token usage:

Strategy 1
BASELINE Strategy

The coordinator delegates directly to executor using the un-optimized baseline prompt (prompts/baseline_prompt.md) to write runs/baseline_solution.py.

Strategy 2
TUNED Strategy

The coordinator first invokes prompt-optimizer (using high-reasoning model) to rewrite prompts/baseline_prompt.md into prompts/tuned_prompt.md, which is then executed by executor.

Evaluation & Metrics Pipeline

After executing both strategies, the run-analyzer agent invokes measure_metrics.py to gather deterministic execution metrics (latency, token usage, cost) and performs static code quality evaluation across baseline and prompt-tuned implementations.

Subagent Team Roster

The 4 specialized agent definitions configured in .opencode/agent/:

Agent Name File Location Model Binding Primary Role
coordinator .opencode/agent/coordinator.md — Orchestrates experiment strategy (BASELINE vs TUNED).
executor .opencode/agent/executor.md gpt-5.6-terra Implements engineering tasks following supplied execution prompts.
prompt-optimizer .opencode/agent/prompt-optimizer.md gpt-5.6-sol Optimizes baseline prompts for requirement clarity, edge cases, and verification checklists.
run-analyzer .opencode/agent/run-analyzer.md gpt-5.6-terra Runs measure_metrics.py & evaluates baseline vs. prompt-tuned code quality.

Strategy Comparison & Architecture Flow

Understanding the trade-offs between un-optimized baseline execution and automated prompt tuning:

Metric / Dimension BASELINE Strategy TUNED Strategy
Execution Flow Coordinator → executor → baseline_solution.py Coordinator → prompt-optimizer (tuned_prompt.md) → executor → tuned_solution.py
Latency & Speed Lowest Latency (Single execution turn) Higher Latency (Optimization turn + Execution turn)
Token Cost Lowest Token Usage Higher Token Usage (Optimization prompt + Extended context)
Code Quality on Simple Tasks 100% Pass Rate (Equal Quality) 100% Pass Rate (Equal Quality)
Code Quality on Complex Tasks Risk of missing edge cases or error handling constraints Superior Modularity, Edge-Case & Error Resilience
Recommended Use Case Simple scripts, rapid prototyping, straightforward tasks Complex multi-step tasks executed by mid/lower-tier models
