Lab 6

Intelligent Failure Recovery

First Choose Intelligently. Then Recover Intelligently.

Overview & Core Concept

In Lab 6, you build a complete autonomous feedback loop: First choose intelligently. Then recover intelligently.

The Autonomous Recovery Loop

Acceptance Test FAILED → Why did it fail? (Diagnostician Agent) → Choose recovery strategy (Recovery Policy) → Retry / Escalate / Stop

When an initial coding agent's implementation fails deterministic verification, a specialized diagnostician agent inspects the test failure stack trace, categorizes the failure (e.g. MINOR_BUG, WRONG_APPROACH, or TEST_INFRASTRUCTURE_ISSUE), and looks up the recovery_policy.yaml to decide whether to retry with the same model, escalate to a stronger model, or stop for human review.

Architecture & Workflow Flow

1. Request (tasks/request_0X.md) 2. Task Classifier (classifier.md) 3. Routing Policy (routing_policy.yaml)
4. Attempt 1 Coding Agent (run_router.py) 5. Deterministic Pytest Verification
PASS → DONE FAIL → RECOVERY

Dual Configuration Policies

Lab 6 relies on two distinct YAML configuration policies in config/:

config/routing_policy.yaml (Initial Routing & Escalation Targets)
version: 1

model_policy:

  implementation:
    primary: terra
    escalation: sol

  debugging:
    primary: terra
    escalation: sol

  refactoring:
    primary: terra
    escalation: sol

  testing:
    primary: terra
    escalation: sol

reasoning_policy:

  low: low
  medium: medium
  high: high
config/recovery_policy.yaml (Failure Strategy Decisions)
version: 1

recovery_policy:

  MINOR_BUG:
    action: retry_same_configuration
    prompt_mode: targeted

  WRONG_APPROACH:
    action: escalate_model
    prompt_mode: targeted

  TEST_INFRASTRUCTURE_ISSUE:
    action: stop
    reason: human_review

Key Takeaways & Engineering Guidance

  • First Choose Intelligently, Then Recover Intelligently: Combining intelligent routing with automated failure recovery creates self-healing agent pipelines capable of fixing edge-case bugs without human intervention.
  • Context Handoff: Attempt 2 receives Attempt 1's generated code plus the diagnostician's precise error analysis, ensuring the second attempt targets the root cause rather than starting from scratch.
  • Cost-Controlled Escalation: Model escalation (`sol`) is triggered only when the failure diagnosis confirms `WRONG_APPROACH`, preventing unnecessary spending on minor syntax fixes.
