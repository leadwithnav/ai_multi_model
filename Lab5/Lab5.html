Overview & Architecture

In Lab 5, an intelligent Task Classifier Agent inspects each engineering request, determines its task type (e.g. implementation, debugging, testing, refactoring) and complexity level (low, medium, high), and delegates execution to run_router.py.

Extracts task_type + complexity

Routing Policy Lookup (config/routing_policy.yaml)
Maps task_type & complexity → Model (sol / terra) & Reasoning (low / medium / high)

Adaptive Routing Principle

Rather than using a static single agent or over-allocating reasoning effort on easy tasks, adaptive routing dynamically pairs model capabilities and reasoning budgets directly to task complexity.

Routing Policy (config/routing_policy.yaml)

The routing policy defines model preferences per workload category and maps complexity levels to reasoning efforts:

config/routing_policy.yaml
version: 1

model_policy:

  implementation:
    primary: terra

  debugging:
    primary: sol

  refactoring:
    primary: terra

  testing:
    primary: terra


reasoning_policy:

  low: low
  medium: medium
  high: high

Key Takeaways & Routing Insights

  • Decoupled Classification: Using a lightweight Task Classifier agent before routing allows the system to make semantic complexity judgments independently of model execution.
  • Policy-Driven Execution: `routing_policy.yaml` centralizes model and reasoning effort mappings so system behavior can be updated without modifying core runner scripts.
  • Cost & Quality Balance: Low complexity tasks route to low reasoning agents (`sol-low`), preserving budget and minimizing latency, while high complexity tasks automatically receive high reasoning effort (`sol-high`).
